# SchemaBridge

SchemaBridge is an AI-assisted data migration workbench for one bounded JSON
dataset. It stores immutable inputs, proposes and versions mappings, validates
every record in a dry run, requires approval before mock execution, and keeps
retry, reconciliation, rollback, and audit evidence.

## Current scope

- One UTF-8 JSON source dataset containing a top-level array of objects.
- One source schema and one target schema per migration workspace.
- Maximum upload size: 20 MB.
- Maximum source records: 10,000.
- Empty datasets are rejected.
- Maximum fields per schema and record: 200.
- Nested objects and scalar arrays are accepted within configured size and
  depth limits.
- Supported types: string, integer, decimal, boolean, date, datetime, array,
  and object.
- Controlled rules support nested-path extraction, text case normalization,
  character removal, scalar-to-text conversion, string splitting, and
  empty-to-null conversion.
- Exactly one required, non-nullable, unique target business key.
- Source undeclared fields are preserved for profiling.
- Target undeclared fields are rejected.
- Arbitrary Python, JavaScript, SQL, and user-defined transformations are not supported.

## End-to-end Phase 1 flow

```text
Create project
→ submit source and target schemas
→ upload JSON records
→ validate limits and structure
→ preserve the original upload
→ create deterministic hashes
→ store an immutable dataset snapshot and source records
→ profile field types, missing values, lengths, and duplicates
→ preserve audit history
```

## First-time setup

Run these commands from the repository root. Copy `.env.example` only when a
local `.env` file does not already exist.

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
cp .env.example .env
npm --prefix frontend install
```

Set `SCHEMABRIDGE_AI_API_KEY` in `.env` before running the AI planner or an
AI-mode evaluation. Gold-pipeline verification does not require an AI key.

## Run the application locally

Start PostgreSQL and apply all migrations:

```bash
docker compose up -d postgres
venv/bin/alembic upgrade head
```

Start the backend in terminal 1:

```bash
venv/bin/uvicorn main:app --host 127.0.0.1 --port 8000 --reload --no-access-log
```

Start the frontend in terminal 2:

```bash
npm --prefix frontend run dev
```

Open:

- frontend: `http://localhost:3000` by default;
- API documentation: `http://127.0.0.1:8000/docs`;
- health endpoint: `http://127.0.0.1:8000/health`.

If port 3000 is occupied, set `SCHEMABRIDGE_FRONTEND_PORT=3001` and
`SCHEMABRIDGE_FRONTEND_ORIGIN=http://localhost:3001` in `.env`. For local
Next.js development, use `npm --prefix frontend run dev -- --port 3001` and
open `http://localhost:3001`. Docker Compose reads the same `.env` values.

Check the backend from a terminal:

```bash
curl http://127.0.0.1:8000/health
```

Expected response:

```json
{"status":"healthy"}
```

`DECIMAL_PARSE_FAILED` on the invalid income. Review and approve the plan,

The current `.env` in this workspace uses frontend port `3001`; the default
`.env.example` uses `3000`.

Inspect service logs when needed:


Stop the application without deleting database volumes:


## Test the complete evaluation pipeline locally

This command does not call the AI provider. It replays all expected proposals
through plan validation, deterministic transformation, target validation and
metric calculation:

```bash
venv/bin/python -m evaluation.run_evaluation \
  --mode gold \
  --dataset all \
  --output-dir evaluation/results/gold-check
```

Generated reports:

```text
evaluation/results/gold-check/
├── predictions.jsonl
├── case_scores.jsonl
└── summary.json
```

Inspect the overall result:

```bash
venv/bin/python -c "import json; print(json.dumps(json.load(open('evaluation/results/gold-check/summary.json'))['overall'], indent=2))"
```

Gold mode replays generated expected plans. Its latency percentiles are empty
because no model is called, and its 100% plan result is a pipeline check rather
than measured AI accuracy.

Run a synthetic API walkthrough, including concurrent retry, reconciliation,
rollback and p50/p90/p95/p99 request timing:

```bash
venv/bin/python -m evaluation.check_workflow --skip-ai
venv/bin/python -m evaluation.check_workflow --skip-ai --workers 4 \
  --output evaluation/results/workflow-check/four.json
venv/bin/python -m evaluation.check_workflow --skip-ai --inject-conflict \
  --output evaluation/results/workflow-check/conflict.json
venv/bin/python -m evaluation.benchmark_records --counts 100 1000 10000
```

Remove `--skip-ai` when inference credits are available. The command creates
a temporary synthetic test account and project, executes the accepted mock
record, and rolls that migration back. Its latency sample is small and is not
a production load benchmark. The records benchmark measures only the
deterministic transformation engine, without uploads or database writes.
The conflict check temporarily changes one synthetic target row, confirms that
reconciliation and rollback detect the mismatch, restores the original row,
and then completes rollback.

Inspect gold-candidate labels before approving them for AI accuracy reports:

```bash
venv/bin/python -m evaluation.review_cases --status
venv/bin/python -m evaluation.review_cases --next
venv/bin/python -m evaluation.review_cases --sample 10
venv/bin/python -m evaluation.review_cases --show exact_copy_001
venv/bin/python -m evaluation.review_cases --approve exact_copy_001 --reviewer "Your name"
```

Approval records are stored in `evaluation/reviews.jsonl` and tied to a hash
of each case's input and expected answer. If a case changes, its approval no
longer applies. Only a reviewer who has inspected the labels should run the
approval command.

## Evaluate the configured AI model

Run a small sample before starting a large evaluation because every case makes
an external model request:

```bash
venv/bin/python -m evaluation.run_evaluation \
  --mode ai \
  --dataset all \
  --one-per-category \
  --limit 10 \
  --concurrency 1 \
  --output-dir evaluation/results/model-sample
```

Read `summary.json` for mapping precision, recall and F1, exact-plan and rule
accuracy, clarification and hallucination results, accepted/rejected record
metrics, and AI latency p50/p90/p95/p99. Check `run.official_gold_evaluation`
before quoting any accuracy number. Small or single-category samples are only
diagnostic; percentiles need enough successful requests to be meaningful.

An earlier Hugging Face token returned HTTP 402 after eight of ten
synthetic original cases on 2026-10-05. Errors are counted
in the report, so this partial result must not be presented as a final score.

For production telemetry, set `SCHEMABRIDGE_OTLP_ENDPOINT` to an OTLP/HTTP
collector base URL, for example `http://otel-collector:4318`. The API then
exports request traces and metrics to `/v1/traces` and `/v1/metrics`. It does
not capture request bodies or authorization headers. When the setting is empty,
telemetry export is disabled; metadata-only JSON request logs still include
request ID, method, path, status, and duration.

## Backup and restore drill

The upload volume and PostgreSQL database both contain migration evidence.
Back up both together during a maintenance window. A database-only archive can
be created for a local restore drill with:

```bash
mkdir -p backups
chmod 700 backups
docker compose exec -T postgres pg_dump -U schemabridge -d schemabridge -Fc > backups/schemabridge.dump
docker compose exec -T api tar -C /app/data/uploads -czf - . > backups/uploads.tar.gz
docker compose exec -T postgres createdb -U schemabridge schemabridge_restore_check
docker compose exec -T postgres pg_restore -U schemabridge -d schemabridge_restore_check --no-owner < backups/schemabridge.dump
docker compose exec -T postgres dropdb -U schemabridge schemabridge_restore_check
```

Store archives securely and set a retention period before production use.
This application preserves approval, execution and rollback history; it does
not automatically delete that evidence. A local restore drill on 2026-10-05
matched project, schema, migration-run and audit-event row totals, then removed
the disposable database.

Resume the same run without repeating successful case IDs; failed cases are
retried, so wait until provider credits are restored before resuming:

```bash
venv/bin/python -m evaluation.run_evaluation \
  --mode ai \
  --dataset all \
  --one-per-category \
  --limit 10 \
  --concurrency 1 \
  --output-dir evaluation/results/model-sample \
  --resume
```

The reports directory is ignored by Git. Evaluation summaries remain marked
`official_gold_evaluation: false` until every selected label is approved by a
human domain reviewer.

In the workbench, the mapping editor can save a reviewed mapping as a new plan
version using the existing plan API. The backend validates its fields and
supported rules. The user then runs the full dry run and explicitly approves
that result before execution. If the AI returns an invalid proposal, the agent
tries one correction; provider errors and timeouts still fail the agent run.

### Hosted model baseline and full-record check

The current default is `Qwen/Qwen3.5-9B:together` through Hugging Face in
`json_mode`, with thinking disabled to avoid spending output tokens on hidden
reasoning. Full migration-plan accuracy has not been measured for it yet.
An earlier `openai/gpt-oss-120b:groq` smoke check on a synthetic, fully
documented customer schema mapped all
11 target fields, produced a valid plan, and transformed the complete record.
With a second record containing `annual_income: "not-a-number"`, the dry run
accepted one record and rejected one with `DECIMAL_PARSE_FAILED` evidence.
These are two smoke checks, not measured accuracy across the gold dataset.

The schema must state business meanings that cannot be inferred safely. The
successful check specified the source date format `%d/%m/%Y`, `YES`/`NO`
boolean meaning, comma-separated interests, and target requirements for a
lowercase email and uppercase country code. Without the target formatting
descriptions, a type-valid dry run preserved an uppercase email and produced
a lowercase country code. Human review of the proposed mapping is still
required before execution.

The pinned Qwen3-4B route returned a provider HTTP 500 on this case. The
pinned Qwen3-32B route produced blocking clarification questions even after
those schema details were provided, and took about 150 seconds with one
correction attempt. Groq rejected this application's strict JSON schema;
`json_mode` succeeded and still passes the Pydantic and plan checks.

Start with one case and a bounded request:

```bash
venv/bin/python -m evaluation.run_evaluation \
  --mode ai --dataset full --limit 1 --concurrency 1 \
  --structured-method json_mode \
  --request-timeout-seconds 120 --max-retries 0 \
  --output-dir evaluation/results/full-one
```

Read `predictions.jsonl` for the exact result. The generated gold labels remain
pending human review, so this command is diagnostic rather than an official
accuracy score. The JSON-mode response must still pass the Pydantic and
deterministic plan checks.


## Free submission deployment

Use Vercel Hobby for the Next.js frontend, a Render Free Docker web service
for the Python API, and Neon Free for PostgreSQL. This is a submission/hobby
setup within the providers' quotas, not a production availability guarantee.
Vercel Hobby is for personal, non-commercial use.

Render Free sleeps after 15 minutes of inactivity and loses local files on
sleep, restart, or redeploy. The current application saves the original
uploaded JSON file locally, so that original-file archive is not durable on
this setup. Parsed source records, schemas, plans, results, checkpoints, and
history remain in the external PostgreSQL database. Keep original input files
locally for the submission. Durable original uploads require an external
storage integration or a host with persistent storage.

### 1. Prepare the repository

Only the root `README.md` is tracked as Markdown. Other Markdown files stay
local. `.env`, uploads, evaluation reports, virtual environments, and frontend
build/dependency folders are ignored. Ignore rules do not remove files from
previous Git commits.

Review and push your submission code to your GitHub repository. Never commit
API tokens, database connection strings, or JWT secrets. Store cloud values in
the hosting dashboards; `.env.example` contains placeholders only.

### 2. Create the database on Neon

Create a Free project, preferably in a region close to your Render service.
Choose PostgreSQL 17 if offered. In the connection dialog, select a direct
connection (connection pooling off) for the app's database and LangGraph
checkpoint connection.

Copy the connection URL privately. Change only the starting scheme from
`postgresql://` to `postgresql+psycopg://`; preserve the hostname, credentials,
and TLS parameters such as `sslmode=require`.

### 3. Deploy the API on Render

Create a Web Service from the GitHub repository:

- Language: Docker.
- Instance: Free.
- Root directory: repository root (leave blank).
- Dockerfile path: `deployment/api.Dockerfile`.
- Docker build context: repository root.
- Health check path: `/health`.

Set this Docker Command in the Render dashboard. It applies migrations before
starting the single API instance; no paid dashboard shell is required:

```sh
/bin/sh -c 'alembic upgrade head && exec uvicorn main:app --host 0.0.0.0 --port ${PORT:-10000} --no-access-log'
```

Add these environment variables in Render, replacing placeholders privately:

```dotenv
SCHEMABRIDGE_APP_ENVIRONMENT=production
SCHEMABRIDGE_DATABASE_URL=<Neon direct URL with postgresql+psycopg scheme>
SCHEMABRIDGE_JWT_SECRET=<new random secret of at least 32 characters>
SCHEMABRIDGE_FRONTEND_ORIGIN=https://YOUR-PROJECT.vercel.app
SCHEMABRIDGE_AI_API_KEY=<your Hugging Face token>
SCHEMABRIDGE_AI_BASE_URL=https://router.huggingface.co/v1
SCHEMABRIDGE_AI_MODEL=Qwen/Qwen3.5-9B:together
SCHEMABRIDGE_AI_STRUCTURED_METHOD=json_mode
SCHEMABRIDGE_AI_MAX_RETRIES=0
SCHEMABRIDGE_AI_TIMEOUT_SECONDS=60
SCHEMABRIDGE_DATABASE_POOL_SIZE=2
SCHEMABRIDGE_DATABASE_MAX_OVERFLOW=2
SCHEMABRIDGE_DATABASE_CONNECT_TIMEOUT_SECONDS=30
SCHEMABRIDGE_STORAGE_ROOT=/tmp/schemabridge/uploads
```

Generate the JWT secret locally with:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Keep `SCHEMABRIDGE_OTLP_ENDPOINT` unset until a collector exists. Deploy and
copy your API URL. Visit `https://YOUR-API.onrender.com/health`; it should
return `{"status":"healthy"}`. This only confirms the health endpoint, not the
complete migration flow.

### 4. Deploy the frontend on Vercel

Import the same repository on the Hobby plan. Choose Next.js, set Root
Directory to `frontend`, and use Node.js 22.x. Use `npm ci` for installation
and `npm run build -- --webpack` as the build command.

Add the following environment variable for the Production deployment:

```dotenv
NEXT_PUBLIC_API_URL=https://YOUR-API.onrender.com/api/v1
```

Deploy, then copy the stable production frontend URL into Render's
`SCHEMABRIDGE_FRONTEND_ORIGIN`. Include `https://` and omit the trailing slash.
Save and redeploy the API. The configured origin permits this exact frontend
URL; per-commit Vercel preview URLs are different origins.

If the API URL changes, update `NEXT_PUBLIC_API_URL` and redeploy the frontend
because Next.js embeds this value during the build. Never put secrets in a
`NEXT_PUBLIC_` variable.

### 5. Submit

Share the stable frontend URL, GitHub repository URL, and root README. Ensure
your reviewer can access the repository and the frontend's deployment access
settings. Mention that the free API can take about a minute to wake up.

The deterministic pipeline previously passed 2,000 generated candidate cases.
The current Qwen model has passed only a short connection check; a complete
AI-assisted migration and browser walkthrough with this model are still
pending. Those deterministic checks are not model accuracy scores. Gold-label
human review and QLoRA are also pending; QLoRA is outside the original required
scope. No live AI evaluation is automatically run as part of these deployment
instructions.

Free hosting does not provide unlimited AI inference. Hugging Face credits
are separate and can run out; check usage before sharing an AI-enabled demo.
Use a small example for the submission instead of a 10,000-record load test.
